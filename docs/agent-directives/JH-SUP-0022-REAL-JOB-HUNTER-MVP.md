# JH-SUP-0022 — Build the Real Job Hunter MVP Now

## Authority / priority

P0. Product Owner explicitly states the priority: **real, currently open jobs that fit the profile**, not more browser-search research.

The previously proven SerpApi Google-search path is now the acquisition mechanism for this MVP. Preserve the canonical `SPRINT_1.md` status as NOT DONE unless the Product Owner separately changes its historical acceptance wording; however, that old browser-SERP acceptance debate must **not block this product increment**.

## Product outcome

Build and execute a minimal end-to-end Job Hunter that takes the committed profile under `profile/`, searches the live web for current job advertisements, checks the actual advertisement details, applies hard exclusions, ranks the remaining jobs, and produces a user-readable shortlist with real application URLs.

This is implementation + live acceptance, not another architecture study.

## Source of truth for fit

Read and use:
- `profile/persona.md`
- `profile/learned_preferences.md`
- `profile/exclusions.yaml`
- `profile/preferred_companies.yaml`

Hard language rule from the current persona:
- **any mandatory intermediate-or-higher English requirement => REJECT**;
- this includes B1/B2/C1/C2, "középfokú", good/communicative/confident/active/fluent/negotiation-level/native-level English when stated as a requirement;
- acceptable: no English requirement; English only as an advantage; explicitly basic/minimal/occasional English that does not require independent professional communication.

Other existing persona exclusions remain binding.

## Search scope

At minimum search current Hungarian opportunities around Budapest/agglomeration plus hybrid/remote roles using the proven SerpApi Google engine. Use multiple focused queries derived from the persona, including at least:

- `IT vezető állás Budapest`
- `informatikai vezető állás Budapest`
- `IT osztályvezető állás Budapest`
- `infrastruktúra vezető állás Budapest`
- `IT projektmenedzser állás Budapest`
- `digitalizációs vezető állás Budapest`
- relevant AI/MI transformation leadership query if useful

Favor real job-detail pages from sources such as Profession and direct employer career pages. Search result pages alone are not enough for final acceptance; inspect the actual listing content when available.

## Required pipeline

Implement a small runnable pipeline with these stages:

1. live search acquisition through the already-proven SerpApi integration;
2. candidate URL normalization and deduplication;
3. job-detail fetch/inspection;
4. extract at minimum: title, company, location/work mode, language requirement, experience requirement, key duties, application URL, source;
5. hard-exclusion gate using `profile/persona.md`;
6. simple transparent relevance scoring against the committed profile;
7. output accepted jobs sorted best-first plus rejected candidates with explicit rejection reason.

Do not invent job facts. If a field cannot be verified, mark it unknown instead of guessing.

## Acceptance run

Run the completed MVP live immediately after implementation.

PASS requires:
- at least 3 **currently reachable, concrete job advertisements** that survive the profile hard exclusions, if 3 genuinely suitable live jobs are discoverable;
- each accepted result has job title, company, location/work mode where available, verified language requirement, application/detail URL, and concise fit rationale;
- any mandatory intermediate-or-higher English role is demonstrably rejected;
- no generic search page is presented as if it were a job advertisement;
- output is generated by the runnable system, not handwritten for evidence.

If fewer than 3 suitable live ads exist after exhaustive focused queries, report the actual count and show the rejection evidence rather than weakening the filters.

## Deliverables

Create a minimal application under a sensible path such as `apps/job-hunter-mvp/` (reuse existing components where appropriate rather than duplicating them).

Create evidence:
- `docs/evidence/REAL_JOB_HUNTER_MVP_LIVE_RUN.md`
- machine-readable live run output under `docs/evidence/` with no credentials/secrets

The human-readable evidence must show the exact accepted jobs and direct URLs, plus a sample of rejected roles and reasons.

## Scheduling

After the live end-to-end PASS, add a low-volume unattended schedule definition for approximately twice per week using the existing server environment. Scheduling must call the same tested pipeline. Do not build notification/email/Telegram features in this directive.

## Finish condition

Update the supervisor ACK with:
- `REAL_JOB_HUNTER_MVP_PASS` if end-to-end live output works, or
- one precise blocker if it does not.

Do not stop at design documentation. Implement, run, and preserve the real results.
