## What changed from the JH-SUP-0022 MVP run

This run reuses the exact same proven acquisition/verification architecture
(SerpApi search → `schema.org/JobPosting` verification → hard exclusions →
transparent scoring). Per this directive's own instruction, the acquisition
mechanism was **not** redesigned. Changes made:

1. **Expanded queries** to also target Pillér-like project/program leadership
   and institutional roles (`informatikai projektvezető`, `digitalizációs
   projektmenedzser`, `IT szolgáltatásmenedzser`, a public-institution query),
   per the Product Owner's positive-pattern refinement in
   `profile/learned_preferences.md`.
2. **New positive scoring**: +20 for genuine project-leadership scope
   (planning, resources/deadlines/risk, stakeholder coordination,
   decision-support language) even without formal people-management, and +10
   for institutional/public-service/utility/large-enterprise context —
   matching the Pillér pattern explicitly.
3. **Three real bugs found and fixed while validating this run's own
   output**, each caught by manually checking specific accepted results
   before finalizing (documented so future runs don't need to rediscover
   them):
   - **Reversed word order in English-level detection.** Hungarian ads often
     write "Angol felsőfokú nyelvtudás" (noun before level), not "felsőfokú
     angol" — the original substring-list check only matched one order and
     missed a mandatory-advanced-English ad. Replaced with a proximity regex
     that matches either order.
   - **Domain-ambiguous English titles accepted without an IT check.**
     "Engineering Manager" and "Operations Manager" alone matched as
     IT-leadership, which incorrectly accepted a MOL Group *oil-refinery*
     engineering-management role. These titles (and bare Hungarian
     "projektmenedzser"/"osztályvezető"/"csoportvezető") now require the
     description to actually confirm an IT/software/digital domain before
     being accepted — this correctly excluded the refinery role, a retail
     department-head role, and a prison-service budget-department role that
     had surfaced from company career-page listings unrelated to the
     matching query.
   - **Semantic duplicates.** The same job can be discovered twice through
     different search queries with different tracking query-strings
     (`profession.hu/...?keyword=...`), which raw-URL dedup does not catch.
     Added a title+company dedup pass keeping the higher-scored copy.
